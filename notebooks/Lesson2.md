## 2.1 Ключевая гипотеза

> **Шаблон:** Если мы предлагаем продукт **A** для сегмента **B** в сценарии **C**, то мы получим метрику **D** не меньше **E** в течение времени **T**, потому что [механизм].

| Продукт (A)                                                    | Сегмент (B)                               | Сценарий (C) | Метрика (D)                                       | Цель (E) | Срок (T) | Механизм                                                                                                                       |
|----------------------------------------------------------------|-------------------------------------------|--------|---------------------------------------------------|------|----|--------------------------------------------------------------------------------------------------------------------------------|
| ИИ-инструмент диагностики диабетической ретинопатии (далее ДР) | Врачи-офтальмологи государственной поликлиники | Профилактический осмотр пациентов с диабетом | Доля заключений ИИ, принятых врачом без изменений | ≥85% | 3 месяца | Модель, имеющая Se ≥ 0.85 и Sp ≥ 0.90 на тестовой выборке, не переобучена и классифицирует снимки на уровне врача-офтальмолога |

## 2.2 Ключевые метрики

### Продуктовые метрики

| Метрика | Целевое значение | Baseline | Способ измерения                                                                                                          | Частота измерений             |
|---------|-----------------|----------|---------------------------------------------------------------------------------------------------------------------------|-------------------------------|
| Доля заключений ИИ, принятых врачом без изменений | ≥85% за 3 месяца | Межэкспертное согласие двух врачей для ДР ~80–85% | Из всех заключений ИИ, выданных за период теста, считаем долю принятых врачом без изменений.                              | По завершению теста прототипа |

## 2.3 Состав прототипа

### Входит

| Компонент                                             | Обоснование                                                                                                        |
|-------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------|
| Бинарная классификация снимков (есть ДР или нет)      | Для задач скрининга достаточно бинарной классификации                                                              |
| Web-приложение (API + простой интерфейс)              | Врачу необходим удобный и понятный способ взаимодействия с моделью, а также возможность зафиксировать свое решение |
| Данные пациентов не храним, максимальная анонимизация | Медицинские данные подпадают под 152-ФЗ; без анонимизации клиника не допустит прототип к тестированию              |

### Не входит

| Компонент                                                        | Причина                                                                                                                                                                      |
|------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Многоклассовая классификация отдельных стадий ДР                 | Компонент не обязателен для скрининга, но открывает перспективу развития продукта в качестве инструмента поддержки клинических решений                                       |
| Сегментация патологических очагов на снимке (микроаневризмы, геморрагии, экссудаты) | Компонент не обязателен для скрининга, но открывает перспективу развития продукта в качестве инструмента поддержки клинических решений                                       |
| Анализ динамики заболевания по снимкам, сделанным в разное время | Компонент не обязателен для скрининга, но открывает перспективу развития продукта в качестве инструмента поддержки клинических решений                                       |
| Возможность просматривать историю инференса                      | Важный компонент будущего продукта, но для прототипа не обязателен. Также есть юридические риски, связанные с хранением медицинских данных                                   |
| Настроенный CI/CD пайплайн + тесты + документация                | Прототип не предназначен для командной разработки и регулярного деплоя. Перечисленное оправдано на production этапе, когда стоит задача масштабировать и поддерживать сервис |

## 2.5 Главный риск

**Риск:** Модель, обученная на открытых данных, не обобщается на снимки из российских поликлиник.

Снимки глазного дна чувствительны к условиям съемки. Кроме того, оборудование разных клиник отличается по производителю и настройкам, методика фотографирования зависит от конкретного специалиста, на линзах могут быть артефакты и дефекты. Все это формирует визуальные паттерны, которых может не быть в обучающей выборке.

---

## 2.6 Конечный формат прототипа

**Формат:** Jupyter-ноутбук + минимальное web-приложение, развернутое на VPS-сервере

Ноутбук содержит:
- Пайплайн предобработки снимков
- Код обучения с логированием метрик
- Чекпоинт лучшей модели
- Итоговую таблицу метрик на val (APTOS) и test (IDRiD)
- Confusion matrix

Web-приложение содержит:
- API для инференса модели (FastAPI)
- Простой интерфейс для загрузки снимка, получения результата и фиксации решения врача (Streamlit)
- Фиксация решений врача в БД для подсчета финальных метрик (PostgreSQL)

## 2.7 Критерии остановки теста прототипа

| Критерий                             | Условие остановки                                                                                     | Комментарий                                                                                                                                                                                 |
|--------------------------------------|-------------------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Временной дедлайн                    | 3 месяца с момента запуска прототипа                                                                  | Основной критерий. Если за данный временной диапазон не была набрана статистически значимая выборка, необходимо либо продолжить тест, либо увеличить кол-во поликлиник для проведения теста |
| Низкая основная метрика              | Доля заключений ИИ, принятых врачом без изменений, < 0.70 за первый месяц с момента запуска прототипа | Останавливаем тест. Дополнительно смотрим на Se и Sp. Делаем предположения о низкой обобщаемости модели. По возможности исправляем и продолжаем тест                                        |
| Технические неполадки с web-сервисом | Полная остановка сервиса, либо увеличенное время анализа одного снимка                                | Останавливаем тест. По возможности исправляем и продолжаем тест                                                                                                                             |
